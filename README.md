## 1. Суть проекта: Система, а не продукт

«Здесь был Буратино» — это ~~не~~ ~~сериал~~ и ~~не~~ ~~один~~ ~~зафиксированный~~ ~~фильм.~~ Это версионный фильм-подкаст, существующий по принципам разработки программного обеспечения.

Проект состоит из двух слоев:
*   **Фабула (Неизменное ядро):** Жизнь Буратино длиной в 30 лет. События фиксированы жестким драматургическим каркасом.
*   **Сюжет (Вариативная оболочка):** Способ рассказа, интонация, монтаж, акценты. Этот слой бесконечно ветвится и обновляется через призму «А что, если?».

**Главная тема:** «Настоящая деревянность». Признание своей природы вместо попытки стать «настоящим мальчиком» (социальным идеалом). Форма проекта (черновики, швы, коммиты) доказывает эту тему на практике.

## 2. Архитектура: Жесткий скелет, гибкая плоть

### А. Фабула (Kernel)
Это неизменный список событий жизни героя.
*   ~~Принцип:~~ Событие факта не меняется.
*   ~~Пример:~~ В точке X герой делает выбор (Киношкола или МБА).
*   ~~Неизменное:~~ В обоих случаях он решает одну и ту же экзистенциальную задачу — поиск себя в чуждой системе.

### Б. Сюжет/Интерпретация (UI)
Это способ проживания события в момент записи.
*   ~~Зависимость от состояния автора:~~ То, как Буратино рассказывает про свой уход из дома, зависит от того, кем автор чувствует себя *сейчас*.
*   ~~Рождение речи:~~ Текст не пишется заранее. Есть только контекст («Я уволился, потому что не мог врать»). Слова рождаются в моменте.

## 3. Технология производства

1.  ~~Подготовка:~~ Прописывается драматургическая карта (список узлов фабулы).
2.  ~~Запись (Коммит):~~ Автор садится перед камерой. Камера фиксирует процесс поиска истины здесь и сейчас.
3.  ~~Ветвление:~~ Один и тот же узел фабулы может быть записан несколько раз с разной интонацией или разным фактическим бэкграундом.
4.  ~~Сборка (Релиз):~~ Из записанных модулей монтируется цельная версия. Зритель видит законченную историю — один из возможных путей по дереву решений.

*   ~~Заметки~~ (о чем я думал перед съемкой).
*   ~~Разные~~ ~~версии~~ (как менялся смысл одной и той же сцены).

**Зачем вам сюда заходить?**

2.  ~~Чтобы~~ ~~скачать~~ ~~материалы:~~ вы можете взять мои черновики и попробовать смонтировать из них свою версию истории.
3.  ~~Чтобы~~ ~~понять~~ ~~структуру:~~ как одна жизнь может иметь десятки разных смыслов в зависимости от выбора.

**Как этим пользоваться?**
Вам не нужно ничего устанавливать. Просто открывайте папки, смотрите видео и читайте заметки. Если хотите собрать свою версию — скачивайте файлы на компьютер и работайте в своем любимом редакторе.

## 5. Модель доступа: «Эталон» и «Производные»

Проект строится на жестком разделении между **Авторским ядром** и **Пользовательским пространством**.

### А. Авторское ядро (The Core)
*   ~~Локация:~~ Главный репозиторий на GitHub и официальный сайт проекта.
*   ~~Статус:~~ Единственный источник истины (Single Source of Truth).
*   ~~Права:~~ Только автор имеет право вносить коммиты и публиковать официальные релизы.

### Б. Пользовательское пространство (The Forks)
*   ~~Локация:~~ Локальные компьютеры зрителей.
*   ~~Статус:~~ Производные работы (Derivative Works).
*   ~~Права:~~ Зритель может скачивать исходники, монтировать свои версии, использовать принципы ветвления для своих проектов.
*   ~~Ограничение:~~ Пользовательские сборки не имеют права позиционироваться как часть официального проекта. Они не попадают в главный репозиторий.

## 6. Философия: Деревянность как фильтр

Проект строится на отказе от попыток казаться «живым» в общепринятом, отполированном смысле.

*   ~~Критика «Быть собой»:~~ Современная культура превратила лозунг «будь собой» в социальную маску. Проект показывает абсурдность этого поиска.
*   ~~Деревянность как честность:~~ Герой признает свою природу. Он остается деревянным — со своими швами, версиями и сомнениями.
*   ~~Отсутствие манифестов:~~ Нет «Гида по деревянности». Зритель либо считывает этот код сразу, либо проходит мимо. Это естественный отбор аудитории.

**Целевая аудитория:** Профессиональное сообщество (фильммейкеры, креаторы), которые устали от необходимости доказывать свою «идеальность» ради карьеры и готовы видеть в «швах» суть творческого процесса.

## 7. Логические узлы и их решение

| Противоречие | Решение |
| :--- | :--- |
| ~~Импровизация vs Драма~~ | Импровизация касается формы высказывания. Смысловая нагрузка жестко задана драматургической картой. |
| ~~Незавершенность vs Релиз~~ | Проект бесконечен как система, но каждый релиз — это завершенный проход по одной из веток фабулы. |
| ~~Открытость vs Авторство~~ | GitHub — это архив для автора. Зрители изучают исходники локально, но не меняют официальную ветку. |
| ~~Деревянность vs Дефект~~ | Деревянность принимается как норма. Непонимание концепции означает несоответствие целевой аудитории. |
